## Executive Summary
This document provides a historical overview of search engine development, tracing the evolution from early non-web tools like Archie to modern, multi-billion dollar industrial search systems. It details the technical architecture of search engines—comprising crawlers, indexers, and query processors—and explains the diverse user needs (informational, navigational, transactional) that these systems aim to satisfy through increasingly sophisticated semantic query analysis.

## Extracted Concepts (7)
- [[Web Crawler]] — A software component that recursively fetches web pages, parses their content to extract new URLs, and builds the corpus for the search index (p. 20).
- [[Inverted Index]] — A core data structure created by the indexer that maps words or tokens to the documents in which they appear, allowing for efficient search retrieval (p. 20).
- [[Query Processing]] — The process of analyzing and interpreting user search inputs to retrieve and rank relevant documents, involving both front-end normalization and back-end matching (p. 20).
- [[User Information Needs]] — The taxonomy of goals that drive a user to perform a web search, typically categorized into informational, navigational, and transactional intents (p. 23).
- [[Gopher Protocol]] — A TCP/IP application layer protocol designed in the early 1990s for the distribution, search, and retrieval of documents, serving as a functional predecessor to the World Wide Web (p. 3).
- [[Paid Inclusion Model]] — A search engine monetization strategy where website owners pay a fee to guarantee that their site appears in search results for specific terms (p. 12).
- [[Pay-per-click Auction]] — A mechanism introduced by Goto.com that allows advertisers to bid for ad positions, paying only when a user interacts with the link (p. 2).
